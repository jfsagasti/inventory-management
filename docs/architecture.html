Factory Inventory Management System

Aplicación full-stack de demostración para gestión de inventario industrial: SPA en Vue 3 sobre una API REST en FastAPI, con datos simulados en memoria y sin base de datos.

Vue 3.4 Vite 5 FastAPI Python 3.11+ Sin base de datos

Visión general

El sistema se reparte en dos procesos independientes que se comunican exclusivamente por HTTP. No hay renderizado en servidor, ni sesiones, ni capa de persistencia: el backend carga siete ficheros JSON al arrancar y los sirve desde memoria.

Arquitectura del sistema

Dos procesos, un único contrato HTTP. El estado vive en memoria del servidor y se reinicia con él.

Stack tecnológico

Frontend · puerto 3000
  • Vue 3.4 con Composition API exclusivamente (sin Options API)
  • Vite 5 como dev server y bundler
  • vue-router 4 en modo history, 7 rutas
  • axios centralizado en api.js
  • Sin Pinia/Vuex: el estado global son ref() a nivel de módulo
  • Sin librería de gráficos: SVG escrito a mano
  • i18n propio (EN/JA) con moneda derivada del idioma
Backend · puerto 8001
  • FastAPI sobre uvicorn, Python 3.11+
  • Pydantic v2 para validación de respuestas
  • uv como gestor de dependencias y entorno
  • Datos en memoria desde server/data/*.json
  • Sin ORM, sin base de datos, sin migraciones
  • Sin autenticación; CORS abierto a todos los orígenes
  • pytest + TestClient en tests/backend/

Flujo de datos

Los cuatro filtros de la barra superior —periodo, ubicación, categoría y estado— son el eje del sistema: viven en un composable compartido y se propagan a cada vista como parámetros de query.

  1. El usuario cambia un filtro

    FilterBar.vue escribe en los ref de useFilters.js. Al declararse fuera de la función del composable, esos refs son un singleton: todas las vistas leen la misma instancia.

  2. La vista reacciona y recarga

    Cada vista observa los filtros y llama a getCurrentFilters(), que devuelve { warehouse, category, status, month } traduciendo el periodo al formato que espera la API.

  3. api.js construye la petición

    Los valores 'all' se omiten del URLSearchParams, de modo que un filtro inactivo simplemente no viaja en la URL.

  4. FastAPI filtra en memoria

    apply_filters() encadena comparaciones sobre las listas cargadas —categoría y estado sin distinguir mayúsculas— y filter_by_month() resuelve tanto meses sueltos (2025-03) como trimestres (Q1-2025) vía QUARTER_MAP.

  5. Pydantic valida la salida

    El response_model de cada endpoint recorta y comprueba los campos antes de serializar. Si un JSON deja de encajar con su modelo, el error salta aquí.

  6. La vista deriva y pinta

    Los datos crudos se guardan en ref; los KPIs, agregados y series de los gráficos se calculan en computed, que se recachean solos cuando cambia el origen.

Observaciones sobre el estado actual

Las tareas llegan de dos sitios a la vez

/api/tasks ya está implementado, pero arranca vacío: las cuatro tareas que se ven al abrir el modal son datos estáticos de useAuth.js, y App.vue las fusiona con las del backend. Por eso los ids del servidor van prefijados (task-1): los de la demo son enteros 1-4 y un id repetido haría que se marcase o se borrase la tarea equivocada.

Backlog.vue no está enrutado

La vista existe y el endpoint /api/backlog funciona, pero main.js no registra ninguna ruta hacia ella, así que no hay forma de llegar navegando.

Los filtros de inventario no tienen dimensión temporal

/api/inventory acepta solo warehouse y category: los registros de inventario no llevan fecha, así que el filtro de periodo no les aplica. Es intencionado, no un olvido.

Sin persistencia y sin autenticación, por diseño

Reiniciar el servidor recarga los JSON y descarta cualquier cambio. CORS admite todos los orígenes y no hay control de acceso ni rate limiting: apto para demo local, no para producción.
